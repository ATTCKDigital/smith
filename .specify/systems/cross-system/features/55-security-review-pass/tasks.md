For a PEM/GCP-JSON match (no useful first/last-chars shape), emit a fixed literal instead (e.g. `[PEM PRIVATE KEY HEADER]`, `[GCP SERVICE ACCOUNT JSON MARKERS]`), never a slice of file content.
  - **Per-line allowlist marker (`research.md` §8):** a same-line trailing `# smith-secret-scan: allow` comment (or the file's native line-comment syntax) suppresses EVERY pattern type on that line — both the entropy heuristic AND the deterministic AWS/GCP/PEM/GitHub/Slack signature matches (quickstart.md Scenario 7 step 2 exercises exactly this breadth). This is the sole false-positive remedy (FR-16) — applied before the scan runs, never after a finding is produced.

  - **Output:** emit `data-model.md` §2's pipe-delimited line format on stdout, one finding per line: `severity|file|line|pattern-id|excerpt-redacted` (severity lowercase `critical|high|medium|low`; `pattern-id` a short stable id per catalogue row, e.g. `aws-akia`, `pem-private-key`, `generic-high-entropy-assignment`, `conn-string-creds`). No other stdout output — anything diagnostic goes to stderr.
